# kcfa

k-CFA abstract interpreter (k = 1) over a CPS-converted Church-numeral program (GTP `kcfa`,
Matt Might / Ben Greenman).

## Module mapping

| Racket                                   | MonNom        | Contents |
|------------------------------------------|---------------|----------|
| `both/structs-adapted.rkt`, `benv-adapted.rkt`, `denotable-adapted.rkt`, `time-adapted.rkt` | `types.mn` | `IExp` (Exp), `IClosure`, `IBinding` (Addr), `IBEnv`, `IDenotable`, `IStore`, `IState`, `IStateSet`, `IAlloc`, `IAtomEval`, `IExpSet`, `IMonoStore`, symbols, tries, list interfaces |
| (Racket builtins)                        | `lib.mn`      | symbols (`Sym`, `SymTable`: interning and `gensym`), `Counter` (eq-hash codes), persistent tries (generated by `../tools/trie_gen.py`), the hash tables `BEnvMap`, `StoreMap`, `MonoMap`, sets `ClosureSet`, `StateSet`, `ExpSet`, cons lists (`../tools/lists_gen.py`) |
| `structs.rkt`                            | `structs.mn`  | `ExpStx`, `Ref`, `Lam`, `Call` (struct subtyping flattened, every class implements the union `IExp`) |
| `benv.rkt` + `time.rkt` + `denotable.rkt`| `benv.mn`     | `Closure`, `Binding`, `Alloc` (the closure returned by `alloc`), `State`; static `Benv`, `Time`, `Denotable` |
| `ai.rkt` + `ui.rkt`                      | `ai.mn`       | `AtomEval` (the closure returned by `atom-eval`); static `Ai`, `Ui` |
| `main.rkt`                               | `main.mn`     | static `Main`, the example programs (generated by `../tools/kcfa_gen.py`) |

Five small modules are merged into two files to keep the configuration count at 486 (with one
file per module and the helper file there would be 13122; the first version, with `benv` and
`denotable` separate, had 1458).

## Deviations

- Racket's immutable `hasheq` tables are persistent 16-way tries keyed by an `Int` id; symbols,
  labels (gensyms) and `Binding` structs get ids from a `Counter` (stand-in for eq-hash codes).
  The `Counter` is passed to `explore`, `next` and `alloc` (extra parameter).
- Sets of opaque structs (`(Setof Value)`, `(Setof State)`, `(Setof Exp)`) compare elements
  with `equal?`, which is `eq?` for these non-transparent structs; they are lists without
  duplicates compared by reference. As in Racket, no state is ever found twice (712 states per
  analysis).
- `hash-update` with a closure is written as `hash-ref` + `hash-set` with the same result.
- The parameter `k` is the constant 1 (it is never parameterized). `format-mono-store` (string
  formatting, never called) is not ported.
- Variables are interned by a number assigned by the generator instead of by name; labels are
  fresh symbols, as `gensym` makes them.
- Generic tries/lists are not used: `new ArrayList<ITrie<E>>()` inside a generic class crashes
  the runtime, and project types inside type arguments of instance-method signatures are not
  devolved by the generator (configurations with removed interfaces aborted with
  `IBEnvEntry<> not found!`).
- Input size is the original (`(main 2 mid-test)`).

## Expected output

Number of variables in the monovariant store and the total size of its sets: `222 333`, from the
Typed Racket version (scratch copy of `main.rkt` that prints them for the last analysis).

## Results

- Fully typed: about 3.2 s (Typed Racket: 1.3 s). The summarizing step (joining the stores of
  all 712 states) dominates, as in Racket.
- `nombench --byfile`: 486 configurations. All 96 configurations without structural files print
  the expected output; 156 of the 390 with records/lambdas do. The other 234 fail at run time:
  `ERROR!` (94, mostly `No such method!`), invalid LLVM code (`Call parameter type does not match
  function signature!` for `Closure`'s constructor, 108), segmentation faults (32).
- Status: PARTIAL.
