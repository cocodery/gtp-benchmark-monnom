# zombie

A zombie game written with closures as objects: every object is a function from a message
symbol to a pair `(message . closure)`, the "fake object types" of `make-fake-object-type*`
(GTP `zombie`, David Van Horn). Replays a recorded history of mouse and tick events.

## Module mapping

| Racket                  | MonNom           | Contents |
|-------------------------|------------------|----------|
| `both/image-adapted.rkt` + types from `zombie.rkt`/`main.rkt` | `types.mn` | `IImage`, `IMouseArgs`, the closure types (`IRealThunk`, `IPosnRealToPosn`, ...), the object types `IPosn`, `IPlayer`, `IZombie`, `IHorde`, `IZombies`, `IWorld` and their message unions `I...Msg` |
| `image.rkt`             | `image.mn`       | `Image`, impl shapes `SceneImpl`, `PlaceImpl`, `CircleImpl`; static `Images` (`empty-scene`, `place-image`, `circle`) |
| `math.rkt`              | `math.mn`        | static `MathRkt` |
| `zombie.rkt`            | `zombie.mn`      | static `Zombie` (constants, `new-...` constructors, `w0`); object classes `WorldObj`, `PlayerObj`, `HordeObj`, `ConsZombiesObj`, `MtZombiesObj`, `ZombieObj`, `PosnObj`; one class per `lambda` (`Fn...`); the message pairs `...Msg...`; static `Getters` (the `posn-x`, ... getters) |
| `main.rkt`              | `main.mn`        | `MouseArgs`; static `Main` (`replay`, `main`) |
| `base/zombie-hist.rktd` | `zombie-hist.mn` | library file (not devolved): the events |

`types.mn` and the message classes / getters of `zombie.mn` are generated by
`../tools/zombie_gen.py` (it plays the role of the `make-fake-object-type*` macro).

## Deviations

- Message symbols (`'x`, `'move-toward`, ...) are `Int` tags (listed in `types.mn`); the result
  union `(U (Pairof 'x (-> Real)) ...)` is an interface with one accessor per payload type, and
  the getter checks the tag as the macro-generated getter does.
- `on-mouse` takes `(x y me)`; lambdas and instance methods with more than two arguments crash the
  runtime, so the three arguments are one `IMouseArgs` object. Mouse event strings are codes
  (0 "enter", 1 "move", 2 "leave"); `(equal? me "leave")` is `me == 2`.
- `Real` is `Float` (all coordinates are exact integers in Racket and stay integral here).
- The image impl is `Any` in Racket and `dyn` here; the three impl shapes are small classes.
- `MT-SCENE` and `PLAYER-IMG` are module-level values in Racket and are rebuilt when used here
  (no static fields); `w0` is built once in `main` before the timer.
- `or` is written with early returns (no short-circuit `||` in MonNom).
- The history is an `ArrayList<Int>` (four numbers per event) built by the library class
  `ZombieHist`; the input-format checks of `replay` are not needed for it.
- `replay` returns the final world (Racket returns `(void)`).
- Input scaling: 100 replays take 0.07 s in MonNom (Racket typed: 0.58 s), so `main` replays the
  history 2000 times. Every replay starts from `w0`, so the result is the same as with 100.

## Expected output

`stop-when` of the final world, the number of image nodes of `to-draw` of the final world and a
checksum of that image (sum over scenes `w+h`, placed images `3x+7y`, circles `radius`):
`#t 9 11149.000000`, computed with the Typed Racket version (scratch copy of `main.rkt` that
returns the final world and prints these values through a small typed helper module).

## Results

- Fully typed: about 1.3 s.
- `nombench --byfile`: 162 configurations. All configurations in which `zombie.mn` is nominal
  (typed or untyped) print the expected output (108). The 54 configurations in which `zombie.mn`
  is structural (its object and closure classes become lambdas, the message pairs records) fail at
  run time: 27 segmentation faults and 27 aborts (`std::exception` thrown while compiling).
  Example: `.BM_SLLLLLLLLLLLLLLLLLLLLLLLLLLLLLLLLLDSSSSSLKKKKKKKKSDKKKKKKKKKKKKKKKKKKKKKKKKKKD`.
