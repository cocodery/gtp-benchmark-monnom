# GTP benchmarks in MonNom

A Submodule of Monnom Project, fully generated by [Claude](https://github.com/claude), check [agent.md](https://github.com/cocodery/monnom/tree/async/.claude/agents/gtp-porter.md). Ports of the [Gradual Typing Performance benchmarks](../gtp-benchmarks/benchmarks) (Typed Racket) to MonNom. Each folder holds a **fully typed** MonNom project that does the same computation as the Typed Racket program and prints a small, deterministic result. The untyped, partly typed and structural configurations are derived from it by the MonNom benchmark generator (`nombench --byfile`).

Each benchmark folder contains:

- `<Project>.mnp` and one `.mn` file per Typed Racket module (some small modules are merged to   keep the configuration count below ~500; see the benchmark's `NOTES.md`), plus `types.mn`   (the adapter / type modules as interfaces) and usually `lib.mn` (stand-ins for the Racket   builtins the program uses: lists, strings, hash tables, `random`, ...). Input data from   `base/` is embedded as a library file (`<libraryfiles>`), which is not devolved;
- `expected.txt`: the result lines (everything after the timing line and the blank line);
- `plotconfig.json`, `configmappings.csv` (identity mapping of the generated configurations); 
- `NOTES.md`: module mapping, deviations, input scaling, expected output and its origin,
  results of all configurations, open issues.

## Running a port

```bash
cd /data/workspace/monnom && . ./setpath.sh
D=$PWD/gtp-benchmarks-monnom/snake; P=$(basename $D/*.mnp .mnp)
nomc -p $D --project $P && (cd $D && nom -p $D -o3 $P)
```

The first output line is the time of the measured region, then a blank line, then the result
lines, which must equal `expected.txt`.

## Regenerating and checking the configurations

```bash
tools/bench.sh <benchdir> [parallel] [timeout]
```

runs `nombench --path <dir> --project <P> --byfile` (generation only), then runs every `.BM_*` configuration once with exactly the command `nombench -r 1` uses (`nom -p <dir> -o3 <P>` in the configuration folder, output to `out1.txt`), but in parallel and with a timeout, compares the result lines with `expected.txt` and writes `configmappings.csv`. Timings measured this way are taken under parallel load; use `nombench --path <dir> --project <P> -r N --byfile` for measurements.

Other helpers in `tools/`:

| Script            | Purpose |
|-------------------|---------|
| `runconfigs.sh`   | run all `.BM_*` configurations (parallel, with timeout) and compare with `expected.txt` |
| `check.sh`        | re-compare existing `out1.txt` files with `expected.txt` |
| `mapping.sh`      | write `configmappings.csv` |
| `classify.sh`     | print, per configuration, whether each file is typed / untyped / structural and whether the output is right (used to find which variants fail) |
| `packhist.py`     | embed a list of small codes (event histories) as packed `Int` words in a library class |
| `textlines.py`    | embed a text file as lists of character codes in a library class |
| `lists_gen.py`    | generate monomorphic cons-list interfaces and classes |
| `trie_gen.py`     | generate monomorphic persistent tries (immutable hash tables keyed by `Int`) |
| `zombie_gen.py`, `kcfa_gen.py`, `zordoz_gen.py` | benchmark-specific code generators (see the NOTES) |
| `textlit.py`      | print the MonNom expression building an `IText` for an ASCII string literal |
| `ifassign.py`     | find `if` branches that assign a local without ending in `return`/`continue`/`break` (the compiler bug below) |
| `renamefields.py` | experiment helper (rename private fields) |
| `runall.sh`       | generate and run all configurations of all (or the given) benchmarks with the runtime `$NOM` in base mode, then rerun the failures with GC off; writes summaries per benchmark (see [Base-mode run](#base-mode-run-of-2026-10-27)) |

Racket reference outputs were computed from scratch copies of the benchmarks (never in `gtp-benchmarks/`) with `require-typed-check` replaced by a local shim that maps `require/typed/check` to `require/typed` (the package is not installed).

"Nominal" configurations are those in which every file is typed or untyped (classes and interfaces); "structural" ones turn some classes into records and lambdas. In every benchmark all nominal configurations print the expected result; the failures of structural configurations are run-time errors of the MonNom runtime (segmentation faults, `UNIMPLEMENTED!`, `No such method!`, invalid generated LLVM code, ...), listed per benchmark in its `NOTES.md` with a command that reproduces one.

## Base-mode run of 2026-10-27

Every configuration of every benchmark was generated with `nombench --byfile` and run once with the runtime snapshot `nom-snapshot/nom-500c674c-20261027` (a copy of `sourcecode/Runtime/nom` built from monnom commit `500c674c`), in base mode: `nom -p <dir> -o3 <P>`, no `--trans`/`--sync`, 16 in parallel, 300 s timeout.

- **4287 of 7938 configurations (54%) print the expected result.** sieve, snake, tetris and zombie pass completely. All failures are in structural configurations (some class turned into a record or lambda). Every nominal configuration passes.
- 2629 of the 3651 failures pass when rerun with `GC_DONT_GC=1`. They are all one runtime bug: records are allocated too small, so their last fields are not traced by the GC (B1).
- The other 1022 failures come from four more runtime bugs (`this` in nested record initializers, records cast to two interfaces, invoking a record with a `this` method, typed record fields that are never cast), one benchmark-generator bug, and two failures that are not yet reduced.

[`bugs/BUGS.md`](bugs/BUGS.md) has the per-benchmark breakdown, the cause of each bug and how the failures were attributed. [`bugs/GtpBugs.mn`](bugs/GtpBugs.mn) has one small test function per bug (all fail on the snapshot). [`bugs/results-500c674c/`](bugs/results-500c674c/) lists the failing configurations with their error lines.

To repeat the run with another runtime, and to rerun the bug tests:

```bash
NOM=$PWD/sourcecode/Runtime/nom gtp-benchmark-monnom/tools/runall.sh /tmp/gtprun   # all benchmarks; or list some
NOM=$PWD/sourcecode/Runtime/nom gtp-benchmark-monnom/bugs/run_test.sh
```

## Porting conventions forced by the current MonNom toolchain

These are workarounds, each recorded in the NOTES of the benchmarks that needed them:

- **Locals assigned inside an `if` branch keep their old value after the `if`** (the compiler's   merge phi node never updates the variable's register). Conditional values are produced with   early `return`s, or the branch ends with `break`/`continue` inside a loop.
- No `?`/`!` nullable types (`T!` values fail casts at run time), no `ifnull`/`ifobj` (they reject the refined variable), no type tests (`if (x : T)` is unimplemented), no downcasts (`(C) i` is rejected statically): unions become interfaces with accessors for every case, `#f`/null become sentinel objects or flags.
- No static fields (accesses are unimplemented), no field initializers: module-level state is created in `main` and passed as extra arguments.
- Strings are opaque and `++` is not implemented by the runtime: strings are `IText` objects holding character codes; output is printed character by character.
- Instance methods and lambdas with more than two parameters crash the runtime: extra parameters are bundled into an argument object.
- A comparison result passed directly as a `Bool` argument crashes the runtime (`GenerateFunctionCall`).
- `Float == x` where `x` comes from an untyped interface method makes the runtime emit invalid   LLVM code; such comparisons go through a small helper in the same file.
- No unary minus on variables (`0 - x`), no float exponent literals, no Float/Int mixing in comparisons, `&&`/`||` do not short-circuit, `private` methods cannot be called with `this.`, keywords `fun`, `in`, `out` cannot be identifiers.
- Benchmark generator: calls to own methods must be written `this.M()`; constructors may only assign every field once; a class that the generator turns into a record must not instantiate itself (the generator recurses forever); project types nested in type arguments of instance-method signatures (`ArrayList<IFoo>`, `Fun<IFoo>`) are not devolved; `ArrayList`s created in untyped code are `ArrayList<dyn>` and fail casts in typed code, so vectors are wrapped in project classes and never cross modules; generic classes cannot create `ArrayList<I<T>>` (runtime crash), so maps and lists are monomorphic (generated).
- The project names `Forth`, `Fsm`, `Lnm` and `Acquire` trigger a runtime loader bug (dangling key in `Loader::GetLibrary`); those projects are named `GtpForth`, `GtpFsm`, ...
- More benchmark-generator limitations found while porting: a class with only a `this` method (turned into a lambda) must be constructed with identifiers as arguments, not nested `new` expressions; a class that constructs itself makes the generator overflow its stack (use a static factory in another class); a 300-deep nested constructor expression made it hang; a class created with `new` in another file is sometimes not found after devolution (use a factory in the defining file); when the generator aborts on one configuration, the configurations after it are written but not compiled.
- Bitwise `&`, `|`, `^` and the power operator `**` (Int and Float) are used directly (jpeg, gregor, mbta, synth, lnm, quadT, quadU); earlier versions of those ports emulated them arithmetically because the runtime lacked them. Shifts are still written as multiplication / floor division by `2 ** n` (no shift operators are used).
- Identifiers that are keywords of the lexer (`shape`, `out`, `in`, `fun`, `default`, ...) cannot be used as names.
